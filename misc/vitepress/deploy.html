构建与部署 ​

使用 Github Actions 自动构建 VitePress 并部署到 Github Pages。

本地构建与预览 ​

使用 docs:build 构建文档：

sh
pnpm run docs:build

构建完成后，生成的内容会输出到 .vitepress/dist 目录。

使用 docs:preview 启动一个本地静态 Web 服务，预览构建的结果：

sh
pnpm run docs:preview

服务默认启动在 4173 端口，通过 http://localhost:4173/ 访问。

设定 public 的根目录 ​

根据部署路径，设置 VitePress 的 base 选项。这个选项应该始终以 / 开头和结尾。

  • 域名根目录：如果站点部署在域名根路径（例如 https://example.com/），base 设置为 /

    js
    export default defineConfig({
  base: '/',
})

  • 子路径：如果站点部署在子路径（例如 https://example.com/docs/ 或 https://<username>.github.io/<repo>/），base 设置为对应的子路径

    js
    export default defineConfig({
  base: '/docs/', // or '/<repo>/'
})

Github Pages ​

Github Pages 可以直接部署在源码仓库。

如果源码仓库是私有的，可以把 Github Pages 部署在一个独立的公开仓库。

方式一：源码仓库 ​

1. 设置 Pages 使用 Github Actions ​

在仓库的 Settings -> Pages -> Build and deployment -> Source，选择 Github Actions。

2. 绑定域名（可选） ​

在域名的 DNS 记录中添加一条 CNAME 类型的记录，目标值为 <username>.github.io。

在仓库的 Settings -> Pages -> Build and deployment -> Custom domain 中填写需要绑定的域名。

3. 禁止搜索引擎收录（可选） ​

在仓库的 Settings -> Secrets and variables -> Actions 选择 Variables，点击 New repository variable 创建一个新的仓库变量：

  • ROBOTS:

    txt
    User-Agent: *
Disallow: /

4. 配置 Github Actions ​

在项目的 .github/workflows 目录下创建 deploy.yml，写入 Github Actions 的配置：

.github/workflows/deploy.yml
yml
# 构建 VitePress 站点并将其部署到 GitHub Pages 的工作流程
name: Deploy VitePress site to Pages

on:
  # 在针对 `master` 分支的推送上运行。如果你
  # 使用 `main` 分支作为默认分支，请将其更改为 `main`
  push:
    branches: [master]

  # 允许你从 Actions 选项卡手动运行此工作流程
  workflow_dispatch:

# 设置 GITHUB_TOKEN 的权限，以允许部署到 GitHub Pages
permissions:
  contents: read
  pages: write
  id-token: write

# 只允许同时进行一次部署，跳过正在运行和最新队列之间的运行队列
# 但是，不要取消正在进行的运行，因为我们希望允许这些生产部署完成
concurrency:
  group: pages
  cancel-in-progress: false

jobs:
  # 构建工作
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v5
        with:
          fetch-depth: 0 # 如果未启用 lastUpdated，则不需要
      - uses: pnpm/action-setup@v4
        with:
          version: latest
      - name: Setup Node
        uses: actions/setup-node@v6
        with:
          node-version: 'lts/*'
          cache: pnpm
      - name: Setup Pages
        uses: actions/configure-pages@v4
      - name: Install dependencies
        run: pnpm install
      - name: Build with VitePress
        run: pnpm docs:build
      - name: Setup robots.txt
        if: vars.ROBOTS != ''
        run: echo -e "${{ vars.ROBOTS }}" > src/.vitepress/dist/robots.txt
      - name: Upload artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: src/.vitepress/dist

  # 部署工作
  deploy:
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    needs: build
    runs-on: ubuntu-latest
    name: Deploy
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4

5. 触发构建 ​

提交并推送代码后，Github Actions 会自动构建并部署。

方式二：独立仓库 ​

  • 源码仓库：项目所在的仓库
  • 部署仓库：部署 Github Pages 的仓库

1. 创建部署仓库的 PAT ​

在部署仓库的 GitHub 账号中，进入 https://github.com/settings/personal-access-tokens，创建一个 Fine-grained token：

  • Repository access：选择 Only select repositories，并勾选部署仓库
  • Permissions：添加 Repositories 类型的权限
    • Metadata：Read
    • Contents：Read & Write

2. 在源码仓库设置 Secret ​

在源码仓库的 Settings -> Secrets and variables -> Actions 选择 Secrets，点击 New repository secret 创建一个新的 Secert：

  • DEPLOY_REPO_PAT：填写部署仓库的 PAT

3. 绑定域名（可选） ​

在域名的 DNS 记录中添加一条 CNAME 类型的记录，目标值为部署仓库的 <username>.github.io。

在源码仓库的 Settings -> Secrets and variables -> Actions 选择 Variables，点击 New repository variable 创建一个新的变量：

  • CNAME：填写绑定的域名

4. 禁止搜索引擎收录（可选） ​

在源码仓库的 Settings -> Secrets and variables -> Actions 选择 Variables，点击 New repository variable 创建一个新的变量：

  • ROBOTS:

    txt
    User-Agent: *
Disallow: /

5. 配置 Github Actions ​

在项目的 .github/workflows 目录下创建 deploy.yml，写入 Github Actions 的配置：

Deploy to public repository 步骤

修改 git remote add origin 后面的 <username> 和 <public-repo>。

.github/workflows/deploy.yml
yml
# 构建 VitePress 站点并将其部署到 GitHub Pages 的工作流程
name: Deploy VitePress site to Pages

on:
  # 在针对 `master` 分支的推送上运行。如果你
  # 使用 `main` 分支作为默认分支，请将其更改为 `main`
  push:
    branches: [master]

  # 允许你从 Actions 选项卡手动运行此工作流程
  workflow_dispatch:

# 设置 GITHUB_TOKEN 的权限，以允许部署到 GitHub Pages
permissions:
  contents: read

# 只允许同时进行一次部署，跳过正在运行和最新队列之间的运行队列
# 但是，不要取消正在进行的运行，因为我们希望允许这些生产部署完成
concurrency:
  group: pages
  cancel-in-progress: false

jobs:
  # 构建工作
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v5
        with:
          fetch-depth: 0 # 如果未启用 lastUpdated，则不需要
      - uses: pnpm/action-setup@v4
        with:
          version: latest
      - name: Setup Node
        uses: actions/setup-node@v6
        with:
          node-version: 'lts/*'
          cache: pnpm
      - name: Install dependencies
        run: pnpm install
      - name: Build with VitePress
        run: pnpm docs:build
      - name: Setup custom domain
        if: vars.CNAME != ''
        run: echo -e "${{ vars.CNAME }}" > src/.vitepress/dist/CNAME
      - name: Setup robots.txt
        if: vars.ROBOTS != ''
        run: echo -e "${{ vars.ROBOTS }}" > src/.vitepress/dist/robots.txt
      - name: Upload artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: src/.vitepress/dist

  # 部署工作
  deploy:
    runs-on: ubuntu-latest
    needs: build
    steps:
      - name: Download artifact
        uses: actions/download-artifact@v4
        with:
          name: github-pages
          path: artifacts

      - name: Extract artifact
        run: |
         mkdir dist
         tar -xf artifacts/artifact.tar -C dist

      - name: Deploy to public repository
        run: |
          cd dist
          git init
          git config user.name "github-actions[bot]"
          git config user.email "github-actions[bot]@users.noreply.github.com"
          git remote add origin https://${{ secrets.DEPLOY_REPO_PAT }}@github.com/<username>/<public-repo>.git
          git checkout -b gh-pages
          git add .
          git commit -m "Deploy from master"
          git push origin gh-pages -f -q

6. 触发构建 ​

提交并推送代码后，Github Actions 会自动构建并部署。

7. 设置部署仓库的 Pages ​

在部署仓库的 Settings -> Pages -> Build and deployment 中：

  • Source 选择 Deploy from a branch
  • Branch 选择 gh-pages
