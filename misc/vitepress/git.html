版本管理 ​

使用 Git 管理项目 ​

  1. 初始化项目

    sh
    git init

  2. 设置默认分支

    TIP

    从 Git 2.28 开始，初始化仓库时默认分支名是 main，而不是 master。

    设置默认的分支为 master：

    sh
    git branch -M master

  3. 设置用户名和邮箱

    sh
    git config --local user.name "<username>"
    sh
    git config --local user.email "<email>"

  4. 设置默认编辑器（可选）

    设置 Git 的默认编辑器为 Vim：

    sh
    git config --local core.editor "vim"

  5. 添加 .gitignore

    在项目的根目录新建 .gitignore 文件，写入忽略提交的内容：

    text
    .DS_Store
node_modules/
src/.vitepress/cache/
src/.vitepress/dist/

  6. 添加文件到版本管理

    sh
    git add .

  7. 创建提交

    sh
    git commit

    提交的 Message 格式参考 Commit Message。第一次提交可以使用：

    text
    feat(site): create project

使用 Github 托管项目 ​

  1. 创建仓库并准备 PAT

    创建一个仓库，然后在 https://github.com/settings/personal-access-tokens 创建一个 Fine-grained token：

    • Repository access：选择 Only select repositories，勾选新建的仓库
    • Permissions：添加 Repositories 类型的权限
      • Metadata：Read
      • Contents：Read & Write
      • Workflows：Read & Write（如果需要使用 Github Actions 自动构建部署才需要）

    INFO

    从 2021 年 8 月 13 日起，Github 不再支持使用用户名密码的方式进行认证，必须使用 Personal access token (PAT)。

  2. 关联远程仓库

    sh
    git remote add origin https://<PAT>@github.com/<username>/<repo>.git

  3. 推送代码

    第一次推送使用 -u 关联远程仓库和本地仓库的分支：

    sh
    git push -u origin master

Commit Message ​

一个完整的 Commit Message 包含三部分：

  • Header：<type>(<scope>): <subject>
  • Body：<body>
  • Footer：<footer>

每部分之间使用空行分隔。

text
<type>(<scope>): <subject>
<BLANK LINE>
<body>
<BLANK LINE>
<footer>
完整示例
text
feat(site)!: remove build plugin

remove legacy build plugin from site configuration
simplify the build process and reduce maintenance overhead
improve stability and make future upgrades easier

BREAKING CHANGE: existing custom plugin hooks are no longer supported
Closes #123, #124

Header ​

Header 是必须的，用于说明提交的简要信息，长度不超过 50 个字符。

  • type：必填，说明提交的类型
    • feat：新增内容
    • fix：修改内容
  • scope：必填，说明提交的影响范围
    • site：范围是站点
    • docs：范围是文档
  • subject：必填，说明提交的内容
    • 使用祈使句，第一人称现在时
    • 以小写字母开头，结尾不加句号或其他标点符号

Body ​

Body 是可选的，用于说明提交的详细信息。要求使用第一人称现在时，每行不超过 72 个字符。

Footer ​

Footer 是可选的，用于说明包含 BREAKING CHANGE，引用链接，工单号或关闭 issue 等，每行不超过 72 个字符。

  • BREAKING CHANGE

    如果包含不兼容的提交，需要在这部分包含 BREAKING CHANGE: <description>，同时需要在 Header 的 subject 前加 !。

    text
    feat(site)!: remove build plugin

BREAKING CHANGE: existing custom plugin hooks are no longer supported

  • 关闭 issue

    使用 Closes #<issueid> 关闭 issue。

    • 关闭一个 issue：

      text
      Closes #1

    • 关闭多个 issue：

      text
      Closes #1, #2, #3
